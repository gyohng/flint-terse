# flint-terse

Teach Flint to use compact mathematical working notes inside `<think>`. Final replies should remain fluent, complete, and appropriately detailed. Training uses the official INT4 MLX checkpoint; deployment uses a merged GGUF in LM Studio.

**Still experimental:** no trained adapter has passed the generation checks. The installed `flint-terse-pilot` only verified export/loading. Attention, output-head, and single-token experiments have reduced thinking length but also caused correctness or formatting regressions. Do not treat them as finished models.

## Setup

Requires Apple Silicon, `uv`, Git and LM Studio. This machine has 128 GB unified memory. Training weights use about 22.6 GB, Q8 deployment about 42 GB, and export needs roughly 170 GB temporary free space.

```sh
./run.sh setup
./run.sh setup-gguf
./run.sh download
./run.sh test
```

Dependencies and model revisions are pinned. The attention-sink gradient implementation and shortest-correct native sampling borrow useful ideas from `../flint-terse2`.

## Corpus

`data/corpus-distilled.jsonl` contains 418 checked examples: 229 math, 154 code and 35 tasks with the real OpenClaw context; 370 train and 48 validation. Most terse traces were generated by Flint after seeing four short thinking demonstrations. The demonstrations are removed from the training prompt. When the terse teacher fails or writes more, selection retains the original checked response. Automatic answer/tests are supplemented by review; they do not prove every reasoning step sound.

To generate more examples, supply JSONL records with `id`, `messages`, `split`, and an answer or executable check. Optional `tools` preserve the real tool schema.

```sh
./run.sh batch-capture prompts.jsonl --samples 2 --batch-size 8 --output runs/native.jsonl
./run.sh distill build prompts.jsonl --output runs/teacher-prompts.jsonl
./run.sh batch-capture runs/teacher-prompts.jsonl --samples 2 --batch-size 8 --output runs/teacher.jsonl
./run.sh distill select runs/teacher.jsonl --baseline runs/native.jsonl --output data/new-corpus.jsonl
```

The source math and code tasks come from [GSM8K](https://github.com/openai/grade-school-math) and [sanitized MBPP](https://github.com/google-research/google-research/blob/master/mbpp/sanitized-mbpp.json). `build-corpus` imports them after `openclaw sync`. Included seeds alone are not enough to establish a useful fine-tune.

`score` and `rewrite` recompute probabilities under each edited prefix. Training can also penalize divergence from the frozen base distribution. Neither small coefficient movement nor low probability distance guarantees preserved behavior; generation checks decide whether a candidate is useful.

## Training and comparison

The scripts expose experimental methods through `--help`: `train` for attention QLoRA, `train-head` for an output-head adapter, and `train-token` for the existing `<think>` embedding. All retain the frozen base checkpoint. The current experiments are not validated recipes.

Use identical prompts, sampling settings and budgets for paired evaluation. Independent per-task random streams prevent one short completion from changing every later task's random draws.

```sh
./run.sh batch-capture data/holdout.jsonl --batch-size 8 --max-tokens 4096 \
  --independent-seeds --output runs/base.jsonl
./run.sh batch-capture data/holdout.jsonl --batch-size 8 --max-tokens 4096 \
  --independent-seeds --adapter adapters/CANDIDATE --output runs/candidate.jsonl
./run.sh compare runs/base.jsonl runs/candidate.jsonl
```

The 159-task holdout is now a development set. A further 100 math/code tasks in `data/final-eval.jsonl` remain unused for adapter selection. The 24 OpenClaw challenges, six multi-turn episodes and ordinary writing/explanation prompts test behavior beyond short numerical answers. `--samples` greater than one is for corpus selection, never evaluation.

## GGUF and OpenClaw

After a candidate passes generation checks:

```sh
./run.sh export --adapter adapters/CANDIDATE --output models/flint-terse-Q8_0.gguf --install
lms load local/flint-terse-Q8_0 --identifier flint-terse --context-length 16384 --parallel 1 -y
./run.sh openclaw condition data/openclaw-eval.jsonl --output runs/openclaw-eval-prompts.jsonl
./run.sh capture runs/openclaw-eval-prompts.jsonl --api http://localhost:1234/v1 \
  --api-chat --model flint-terse --temperature 1 --max-tokens 4096 --output runs/openclaw-terse.jsonl
./run.sh replay data/openclaw-episodes.jsonl --model flint-terse --temperature 1 --output runs/episodes-terse.jsonl
```

Use the installed key from `lms ls` if it differs. Export merges the adapter, restores HF expert tensors, and uses the pinned llama.cpp converter. Temporary full-precision shards are removed afterward. Q8 limits additional quantization error; it cannot recover precision already lost in the INT4 base. Compare deployed behavior as well as native MLX results.

`openclaw sync` reads the authorized remote system context and exec/process schemas over SSH. Episode replay feeds actual model responses back into the conversation with fixed tool observations. Generated tool calls are checked, not executed.

## Research

[ConPress](https://arxiv.org/abs/2602.01472) studies concise reasoning SFT; [ShorterBetter](https://arxiv.org/abs/2504.21370) uses shortest-correct rollouts for RL. [Prompt tuning](https://arxiv.org/abs/2104.08691) motivates learning a small input representation with a frozen transformer. These inform experiments, not a claim of a universally best method or reproduced published gains on Flint.

[Flint's model card](https://huggingface.co/RecursiveSI/flint) recommends temperature 1, top-p .95 and top-k 20. Our 4,096-token comparison budget measures practical local behavior, below its recommended budget for hard problems.
